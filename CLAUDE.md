# us-stock-agent

Multi-agent paper-trading (forward test) system for US stocks/ETFs the owner would buy via Dime (Thai UI). Owner approves every order. Python agents + Cloudflare Worker + static assets + D1.

- Deploy: push to `main` → Cloudflare Workers Builds runs `npx wrangler deploy` (web only). Python agents run on GitHub Actions (`.github/workflows/agents.yml`, workflow_dispatch only). Scheduling lives in the Worker's Cloudflare cron watchdog (`scheduled` → `watchdog`, every 30 min 06:00–11:59 TH): GitHub's own schedule never fired, and Yahoo publishes the previous NY close only around 10:00 TH (missing at 08:17 TH on 2026-10-22). Daily = Tue–Sat from 10:20 TH if no `data` journal row today whose detail.last ≥ yesterday; weekly = Sat from 11:00 TH if no `เริ่มรอบรายสัปดาห์` row with detail.data ≥ Friday; skips while a run is queued/in progress; at most one dispatch per window (journal `system` `watchdog: สั่งรัน <mode>`), using the GitHub token saved on the settings tab. The `data` journal row carries download diagnostics (raw_last, spy_last, ny_now).
- Nine portfolios run side by side on the same $10k each (`strategies/`): momentum (weekly, 6-pick), dual_momentum (monthly, asset-class switch), risk_parity (monthly, inverse-vol), ai_pick (weekly, Claude chooses weights under the same Risk Manager), ai_sector (monthly, added 2026-10-24 on the owner's request: Claude picks weights among the 11 Select Sector SPDR ETFs + SPY + SHY with tools sectors / price_history / sector_stocks / check_risk / submit; per-strategy caps ETF ≤ 40%, group ≤ 40%; packet keeps `rule_weights` = rule "Top 3 + trend" from research/sector_etfs.py as the comparison), breakout = "W1 เทรดรอบ" (added 2026-10-29, owner's choice, auto-approved: `strategies/breakout.py`, its own daily engine called from `orchestrator.daily` — breakout of 55-day high + SMA200 + SPY > SMA200, 5% per position, ≤ 20, stop 3 ATR then trailing 6 ATR checked against the day's low like a resting stop order, kill switch stops new entries only; params config.BREAKOUT; per-position stops in portfolio state `stops`, pending signal info in `pending`; no 3% open-gap hold rule), momentum_wide = "Momentum กว้าง" (added 2026-10-29, waits for owner approval like momentum: same momentum rules, universe extended only while its own packet is built via `breakout.wide_universe` + `breakout.wide_data`). Universe for both: shared state `breakout_universe` rebuilt weekly from SEC company_tickers_exchange + frames dei shares × last close (≥ $2B, ≥ $10M/day traded, NYSE/Nasdaq, S&P 500 always in); non-S&P names are never added to config.UNIVERSE permanently, so the other portfolios cannot see them. load_data downloads held + approved/proposed tickers outside the S&P 500 as extra. ai_pick_opus / ai_sector_opus (added 2026-10-29, owner's choice, auto-approved) = exact twins of ai_pick / ai_sector with model config.CLAUDE_MODEL_OPUS (registry `model: "opus"` → orchestrator passes extra model + agent=P; llm.run_agent(model=...) logs the model in the journal); all other AI calls stay on config.CLAUDE_MODEL (Sonnet). Purpose: does a stronger model pick better — compare twins forward only. Keys are DB values; never rename. Monthly strategies decide only on the last Friday-signal of the month (`_is_month_end_week`, calendar-based; same rule in backtest) except their very first packet.
- Universe (owner's choice 2026-10-21): fixed ETFs/defensive in config.FIXED + every S&P 500 stock from `universe/sp500.csv` (datasets/s-and-p-500-companies; cloud runs refresh it online each run, fallback = file). Yahoo symbols (BRK-B); groups from GICS sector (GOOGL/META = comm). `config.info(t)` for any lookup — a held stock that left the index gets group other, is still downloaded (extra=) and Risk Manager sells it. Only core tickers (ETFs/defensive/SPY/FX) failing data = auditor fail; missing single stocks are just warnings. News + ai_pick look at held stocks + top 30 momentum stocks (`regime_agent.top_stocks`, `orchestrator.watchlist`), not all 500. Backtest uses today's list → survivorship bias (noted on the web).
- D1 `us-stock-agent` id `34da2387-758f-4ebd-b51e-a4717151be72`. Every portfolio table has a `portfolio` column (state/positions/packets/orders/equity/journal/backtests); shared values use portfolio=''. `paper.py` scopes by `paper.CURRENT` via `with paper.portfolio(name)`. docs(coll,id,data) holds secrets only. Migrated from single-portfolio on 2026-10-21 (`migrate_v2.sql`, kept for reference).
- Agents write through POST /agent/sql (SQLite statements, D1 batch). Auth: GitHub Actions OIDC token (iss token.actions.githubusercontent.com, aud `us-stock-agent`, repository = env.AGENT_REPO, ref refs/heads/main) — no GitHub secrets needed; or Bearer token whose SHA-256 (base64url) = docs secrets/agent.hash (owner's PC backup, token in local `.env`). /agent/sql refuses any statement touching `docs`.
- `paper.py` switches backend: WORKER_URL + (AGENT_TOKEN or ACTIONS_ID_TOKEN_REQUEST_URL) → D1 via Worker; otherwise local SQLite data/invest.db. Same SQL both ways (cloud and local runs verified identical).
- In the cloud the data agent never falls back to synthetic data; a failed yfinance download stops the run.
- Web login: env.APP_PASSWORD if set, else PBKDF2 hash in docs secrets/auth (changeable on the settings tab). Finnhub key (live quotes) and Anthropic key are entered on the settings tab, AES-GCM encrypted in docs secrets/{finnhub,anthropic} (key derived from the session secret), never sent to the browser. Agents fetch the Anthropic key via GET /agent/secret?name=anthropic (same auth as /agent/sql); `agents/llm.py` is the only Claude client.
- News agent (`agents/news_agent.py`): once a day (`orchestrator.news_today`, shared state `news_digest`, reused by the weekly run) reads 7 days of news for the watchlist (held + top 30 momentum stocks) — SEC EDGAR 8-K first (`agents/edgar.py`: data.sec.gov submissions by CIK from sp500.csv, Exhibit 99 press-release text, ≤10 req/s, User-Agent config.SEC_USER_AGENT / env SEC_CONTACT; items 1.03/4.02 → block and 3.01/4.01/2.04 → caution decided by code, still applied if Claude fails), then Finnhub company-news (headline+summary+link; agents get the key via /agent/secret?name=finnhub) with yfinance fallback; earnings date from Finnhub calendar → caution within 5 business days (code decides, not AI). One Claude call → per stock flag + items {type product/earnings/deal/regulatory/management/analyst/other, tone, importance 1–3, th, links}. Effects (owner's rule kept): block applies to every portfolio; good news (e.g. new product) is fed only to ai_pick and shown on the overview news panel + reports — the 3 rule strategies stay untouched as a clean comparison.
- ai_pick is a tool-using agent (`strategies/ai_pick.py` Research tools: screen / price_history / fundamentals (Finnhub stock/metric) / news / check_risk / submit, all price data cut at the signal date; loop = `llm.run_agent`, ≤14 turns, ≤25 tool calls). Its research trail is stored in packet data `ai_research` and shown on the decision tab. Owner's choice 2026-10-22 (ai_pick) and 2026-10-24 (ai_sector): `config.AUTO_APPROVE` (ai_pick, ai_sector, breakout, ai_pick_opus, ai_sector_opus) — its orders are approved automatically when the auditor does not fail (packet status `decided`, order note อนุมัติอัตโนมัติ); every other portfolio still waits for the owner. Weekly skips a portfolio while it still has approved/held orders waiting to fill.
- AI agents are filters only: news (block/caution per stock), macro (risk_level high → exposure ×0.7), reporter (prose; numbers come from the template). ai_pick is the one AI that proposes weights, and Risk Manager caps it like any other strategy; its auditor check is rule-based, not a recompute. Any Claude failure falls back to "no effect" and is logged. No ANTHROPIC key set → all AI off, ai_pick holds cash/previous.
- Backtest covers the 3 code strategies only (AI knows the past). XLB/XLRE/XLC have kind `sector` (config.FIXED end, generated last in synthetic data) so momentum/regime/ai_pick never see them; config.RISKY_KINDS = etf/stock/sector for Risk Manager, auditor, reporter. Research findings so far: notes/research-log.md (no stock-picking or sector rule beat SPY in both search and validate). Local dev: `.dev.vars` may set OIDC_ISSUER and JWKS_TTL_MS=0 for a fake issuer; never set in production.
- Intraday view (owner's choice 2026-10-22, display only): Worker cron `*/15 13-21 * * 1-5` → `snapshot` (only 09:30–16:05 NY on weekdays) prices held tickers + SPY via Finnhub, writes table `intraday(portfolio, ts, usd)` (portfolio 'SPY' = buy-and-hold benchmark from momentum's bench_start/capital), keeps 10 days; GET /api/intraday?days=; overview chart toggle ระหว่างวัน/รายวัน and a live 'วันนี้' % on each KPI card. Official closes still come only from the daily run.
- Per-stock charts: the daily run's `publish_prices` writes closes of held tickers + latest packet targets + SPY into table `prices(ticker, date, close)` (~380 days for a new ticker, then the last 10 days each run). GET /api/prices?tickers=&days= (sparklines in the holdings table), GET /api/stock?ticker=&portfolio= (closes + that portfolio's filled orders + position) → chart panel with cost line and buy/sell markers.
- Timing (owner's concern 2026-10-23: a midweek weekly run made momentum propose a new set right after the old one filled): `_weekly_one` creates a packet only when the signal date is the week's last close (`_is_week_close`: Friday, or Thursday when run on the weekend after a Friday holiday), except a portfolio's first packet. Approved orders fill at the first NY 09:30 open after decided_at (20:30 TH in US summer time, 21:30 in winter). POST /api/orders/cancel cancels approved orders only before that open (`fillOpenMs` in worker.js and index.html, same rule as `_fill_orders`); afterwards the trade counts as done even though the morning run records it later. The web shows these deadlines and labels past-open approved orders ซื้อขายแล้ว รอบันทึก.
- Web can only: read, approve/reject orders, cancel approved orders before the open (not for packets whose auditor failed), kill switch/resume, settings. Risk limits live in config.py only.
- Agents: orchestrator(1) data(2) regime(3) signal(4) news(5, Claude, off) risk(7) backtest(9) auditor(10) reporter(11). Weekly signal on Friday close, fills at next open after approval; approvals expire after 3 business days; >3% price move holds the order.
- Tests: `python -m tests.test_system` (per strategy: null test on random data, lookahead, risk limits, forward-vs-backtest consistency ≤1%; AI test with a scripted fake Claude proves Risk Manager/news/macro clamp the AI). Local web: start.bat → server.py (localhost:8000, has simulate + editable backtest).
