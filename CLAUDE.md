# us-stock-agent

Multi-agent paper-trading (forward test) system for US stocks/ETFs the owner would buy via Dime (Thai UI). Owner approves every order. Python agents + Cloudflare Worker + static assets + D1.

- Deploy: push to `main` → Cloudflare Workers Builds runs `npx wrangler deploy` (web only). Python agents run on GitHub Actions (`.github/workflows/agents.yml`): daily Tue–Sat 06:30 TH, weekly Sat 09:00 TH (+ backtest).
- Four portfolios run side by side on the same $10k each (`strategies/`): momentum (weekly, 6-pick), dual_momentum (monthly, asset-class switch), risk_parity (monthly, inverse-vol), ai_pick (weekly, Claude chooses weights under the same Risk Manager). Keys are DB values; never rename. Monthly strategies decide only on the last Friday-signal of the month (`_is_month_end_week`, calendar-based; same rule in backtest) except their very first packet.
- D1 `us-stock-agent` id `34da2387-758f-4ebd-b51e-a4717151be72`. Every portfolio table has a `portfolio` column (state/positions/packets/orders/equity/journal/backtests); shared values use portfolio=''. `paper.py` scopes by `paper.CURRENT` via `with paper.portfolio(name)`. docs(coll,id,data) holds secrets only. Migrated from single-portfolio on 2026-10-21 (`migrate_v2.sql`, kept for reference).
- Agents write through POST /agent/sql (SQLite statements, D1 batch). Auth: GitHub Actions OIDC token (iss token.actions.githubusercontent.com, aud `us-stock-agent`, repository = env.AGENT_REPO, ref refs/heads/main) — no GitHub secrets needed; or Bearer token whose SHA-256 (base64url) = docs secrets/agent.hash (owner's PC backup, token in local `.env`). /agent/sql refuses any statement touching `docs`.
- `paper.py` switches backend: WORKER_URL + (AGENT_TOKEN or ACTIONS_ID_TOKEN_REQUEST_URL) → D1 via Worker; otherwise local SQLite data/invest.db. Same SQL both ways (cloud and local runs verified identical).
- In the cloud the data agent never falls back to synthetic data; a failed yfinance download stops the run.
- Web login: env.APP_PASSWORD if set, else PBKDF2 hash in docs secrets/auth (changeable on the settings tab). Finnhub key (live quotes) and Anthropic key are entered on the settings tab, AES-GCM encrypted in docs secrets/{finnhub,anthropic} (key derived from the session secret), never sent to the browser. Agents fetch the Anthropic key via GET /agent/secret?name=anthropic (same auth as /agent/sql); `agents/llm.py` is the only Claude client.
- AI agents are filters only: news (block/caution per stock), macro (risk_level high → exposure ×0.7), reporter (prose; numbers come from the template). ai_pick is the one AI that proposes weights, and Risk Manager caps it like any other strategy; its auditor check is rule-based, not a recompute. Any Claude failure falls back to "no effect" and is logged. No ANTHROPIC key set → all AI off, ai_pick holds cash/previous.
- Backtest covers the 3 code strategies only (AI knows the past). Local dev: `.dev.vars` may set OIDC_ISSUER and JWKS_TTL_MS=0 for a fake issuer; never set in production.
- Web can only: read, approve/reject orders (not for packets whose auditor failed), kill switch/resume, settings. Risk limits live in config.py only.
- Agents: orchestrator(1) data(2) regime(3) signal(4) news(5, Claude, off) risk(7) backtest(9) auditor(10) reporter(11). Weekly signal on Friday close, fills at next open after approval; approvals expire after 3 business days; >3% price move holds the order.
- Tests: `python -m tests.test_system` (per strategy: null test on random data, lookahead, risk limits, forward-vs-backtest consistency ≤1%; AI test with a scripted fake Claude proves Risk Manager/news/macro clamp the AI). Local web: start.bat → server.py (localhost:8000, has simulate + editable backtest).
- Owner's local copy: D:\AI\Invest Agent\US Stock (keep in sync).
